# 시화산노회 바깥 보안 점검 (교회 컴퓨터)

교회 컴퓨터가 매일 오전 6시 30분에 홈페이지 바깥을 점검하고, 결과를 Supabase 로 넘깁니다.
Supabase 는 자기 안의 점검(`supabase/126_security_check.sql`)과 합쳐 **하나의 보고**를 만들고,
최고관리자 알림함으로 알립니다 — 「위험」은 그날 바로, 월요일에는 한 주 요약.
보고는 홈페이지 **시스템 운영 → 보안 점검** 탭에서 봅니다.

## 무엇을 보나

| 대상 | 점검 |
|---|---|
| 홈페이지 | 열리는가 · http→https 로 넘기는가 · 외부 라이브러리 버전 고정 · `.env`·봇 설정·비공개 폴더가 주소로 열리는가 |
| Cloudflare 서버 6곳 | AI·영수증·증명서·녹음·자료·사진이 로그인 없는 요청을 거절하는가 · CORS |
| Supabase | 로그인하지 않은 사람이 회원·명단 생년월일·서류·알림·감사 기록·장부·회의록 등 14개 표를 읽을 수 없는가 · 가입 설정 |
| GitHub 저장소 | 지금 공개된 **모든 파일**과 최근 하루 변경(월요일엔 **지난 기록 전체**)에 비밀 열쇠(Supabase 서비스 키·Anthropic/OpenAI 키·개인 키·GitHub/텔레그램/Slack 토큰)가 있는가 · 올라가면 안 되는 파일 |

## 처음 한 번

1. Supabase SQL Editor 에서 `supabase/126_security_check.sql` 을 실행합니다.
2. 이 폴더의 **`보안점검 등록.bat`** 을 두 번 누릅니다. 매일 오전 6시 30분 점검이 등록되고, 바로 한 번 점검해 볼 수 있습니다.
   - `config.json`(이 컴퓨터의 점검 열쇠)이 없으면 새로 만들고, Supabase 에서 실행할 한 줄을 보여 줍니다.
   - Node.js 가 있어야 합니다.

## 단추

| 파일 | 하는 일 |
|---|---|
| `보안점검 등록.bat` | 매일 점검 등록 (작업 스케줄러 「Sihwasan Security Watch」) |
| `보안점검 지금.bat` | 지금 점검하고 보고 |
| `보안점검 확인처리.bat` | 저장소에서 찾은 열쇠를 **폐기·재발급했거나 예시값으로 확인한 뒤** 다음부터 건너뛰게 함 |
| `보안점검 해제.bat` | 매일 점검 해제 |

마지막 점검 결과는 이 폴더의 `last-run.log` 에 남습니다.

## 열쇠

- `config.json` 의 `watchSecret` 이 이 컴퓨터의 점검 열쇠입니다. **저장소에 올라가지 않습니다**(`.gitignore`).
- Supabase 에는 그 열쇠의 지문(SHA-256)만 있습니다.
- 다른 컴퓨터로 옮기거나 열쇠가 새었으면 `node watch.js --new-key` 를 실행하고, 보여 주는 한 줄을 Supabase 에서 실행합니다.

## 교회 컴퓨터가 꺼져 있으면

오전 7시 30분(Supabase 예약) 또는 누가 홈페이지에 들어올 때 DB 점검만으로 보고하고,
「바깥 점검이 오지 않았습니다」를 주의로 알립니다.
